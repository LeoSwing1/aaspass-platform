# Block 9 — Customer Identity & Customer 360

## Objective
Give every customer a durable human-readable AasPass Customer ID and allow authorized Support/HQ staff to retrieve a complete customer support context using the registered mobile number.

## Customer ID
Format: `AAS-CUS-######`

Generated by PostgreSQL sequence + customer profile trigger. The ID is independent of phone number and remains stable if the customer changes phone number through an approved account process.

## Customer 360 data
- Customer ID
- Name
- Registered mobile
- Email
- Account status
- Created date
- Order count
- Active order count
- Total non-refunded order value
- Last order
- Saved addresses
- Recent orders and payment states
- Active delivery/order context
- Support history
- Cart summary
- Active device registration summary

## Support access
Primary lookup:
`GET /api/v1/support/customers/lookup?phone=<registered-mobile>`

Alternative:
`GET /api/v1/support/customers/<AAS-CUS-######>`

Access requires authentication + `VIEW_CUSTOMER_PROFILE`.

Lookup is audited with customer code and only the last four phone digits in the audit metadata.

## Customer app
The Profile surface shows the Customer ID and links into:
- Addresses
